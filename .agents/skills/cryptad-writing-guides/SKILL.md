# Cryptad writing guides

Use the relevant guide for substantive prose work; an isolated typo does not require every guide.

- [Writing style](references/writing-guide.md): shared voice, terminology, and evidence.
- [Documentation](references/docs-guide.md): README/docs structure, commands, and links.
- [Engineering articles](references/blog-guide.md): long-form technical explanations.
- [Release notes](references/release-notes-guide.md): operator impact and shipped changes; use
  [release-note workflow](../cryptad-write-release-notes/SKILL.md) for source and frozen-note contracts.

Keep facts grounded in code or authoritative runbooks. Preserve integer build tags.
Distinguish prepared, validated, authorized, and independently verified publication.
For Stable maintenance or lifecycle prose, consult the corresponding canonical runbook only when
those operations are in scope. Keep lifecycle descriptors separate from immutable release artifacts.

Before using Mail

Compare full contact fingerprints through a trusted separate channel. A self-signed contact proves control of a key, not a person's identity. Send and fetch require your explicit action.

Inserted means encrypted content entered the network; it does not mean delivered or read. Exchange the resulting CHK reference manually. Opening Mail or a contact does not send, fetch or acknowledge messages.

No automatic inbox delivery, anonymity, forward secrecy, SMTP/IMAP or Freemail compatibility. This composition has no independent security review or production certification. Endpoints, daemon and vault must remain trusted.

Support: crypta-core, repository issue tracker. Never include message text, contact cards, CHK references, backups or private diagnostics in public reports.

Permission disclosure

Mail uses app-scoped encrypted durable data, dedicated non-exportable vault identities, a fixed own-app worker channel, generated ciphertext insertion, queue status and bounded Crypta content fetch. New cryptographic operations are process-only. The browser has no private key or process token access.

  • mail.control operates the fixed own-app worker channel.
  • vault.identities.read reads retained public identity metadata.
  • vault.identities.create creates dedicated independent Mail identities.
  • vault.mail.sign signs validated Mail objects in the worker.
  • vault.mail.open opens authenticated recipient envelopes in the worker.
  • vault.mail.storage protects app state under a separate storage purpose.
  • app.data.read restores encrypted app-owned state.
  • app.data.write commits encrypted state and replay evidence atomically.
  • queue.read checks explicit insertion progress.
  • queue.write queues or retries committed ciphertext.
  • content.insert.app-document inserts generated encrypted envelopes.
  • content.fetch fetches only explicitly approved bounded references.

Compose and explicitly send

Import a manually received reference

To reply, select the sender's approved contact, compose a new draft and repeat the explicit send and reference handoff.

Retry and recovery

Retries reuse sealed bytes. An uncertain publication outcome cannot establish exactly-once network insertion.

A data backup contains no private keys. Missing keys mean key-unavailable. Do not generate replacement keys and expect old data to recover. Restore merges available replay evidence and pauses new sending and receiving; this prototype has no resume operation after restore. Retained messages remain readable. Default uninstall deletes required vault keys even if app data is preserved, making data-only backups unreadable. Bundle rollback does not restore data or grants.
